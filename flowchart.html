Lead Manager – Data Flow Diagram

ภาพรวมการไหลของข้อมูลจริงในโปรเจกต์: Vue → AppState → Store → Dexie และ ฟังก์ชัน LeadApp / AppGui / Utils ที่เกี่ยวข้องทั้งหมด

Vue 3 + Dexie + UI Memory (Store)
Flow 1

โหลดข้อมูลครั้งแรกจาก Dexie → Store → AppState Startup & Sync

ตอนที่ app.js ทำงาน setup() จะเรียก LeadApp.loadAll() เพื่อดึงข้อมูลจาก IndexedDB (Dexie) แล้วอัปเดตเข้า Store.data.leadItems จากนั้น AppGui.setupComputed() จะตั้งค่า AppState.filteredLeads ให้เฝ้าดูข้อมูลชุดนี้ตลอดเวลา

app.js → LeadApp.loadAll() Dexie: AppDexie.lead.getAll() Store.setItems("Lead", items) AppGui.setupUIMainComputed() AppState.filteredLeads (computed)

สายข้อมูลหลัก: Dexie (ฐานข้อมูล) → Store (UI Memory) → AppState (Computed + Ref)

  • LeadApp.loadAll() เรียก AppDexie.lead.getAll() แล้วเอา Array ของ Lead ที่ได้มาส่งเข้า Store.setItems("Lead", items)
  • Store.setItems() แทนที่ Store.data.leadItems ทั้งก้อน (เปลี่ยน reference) ทำให้ Vue เห็นการเปลี่ยนแปลงแบบรวดเร็ว
  • AppGui.setupUIMainComputed() สร้าง AppState.filteredLeads เป็น computed ที่เฝ้าดูทั้งคำค้นหาและ Store.data.leadItems ตลอดเวลา

เพิ่ม / แก้ไข / ลบ Lead และการ Sync กลับเข้า UI CRUD

เวลาเพิ่ม, แก้ไข หรือ ลบ lead จะทำผ่าน LeadState.form + ฟังก์ชันใน LeadApp ที่คุยกับ AppDexie.lead.* แล้วเรียก loadAll() อีกรอบเพื่อ sync UI ให้ตรงกับฐานข้อมูลเสมอ

LeadState.form (v-model) LeadApp.add() / update() / delete() AppDexie.lead.add / update / delete เรียกซ้ำ LeadApp.loadAll() AppNotifications.show(...)

สังเกตว่า ทุก CRUD จบด้วย await this.loadAll() เพื่อให้ Store และ AppState ตามฐานข้อมูลจริงตลอดเวลา

  • add() สร้าง id ใหม่ด้วย crypto.randomUUID() + เซ็ต createDate เป็นวันที่ปัจจุบัน
  • update() เช็คก่อนว่า LeadState.form.id มีจริงหรือไม่ ถ้าไม่มีจะ console.warn แล้วหยุดทำงาน (ตัวดักกันข้อมูลเพี้ยน)
  • delete(id) รับ id มาจาก UI แล้วส่งต่อให้ AppDexie.lead.delete(id) ลบจริงใน DB
  • หลังจาก CRUD แต่ละครั้ง จะเรียก loadAll() + ปิด Modal + แสดง Notification
Flow 3

การค้นหา (Search) + Debounce + FilterLeads Filter

ตัวดักสำคัญ: clearTimeout(searchDebounceTimer) กัน watcher ยิงซ้ำ, และ เช็ค query ว่าง ใน filterLeads() ถ้าว่างก็คืน list เดิมทั้งหมด

  • ใน Utils.filterLeads() ถ้า !Array.isArray(list) จะคืน [] ทันทีป้องกัน error เวลา list เป็นค่าเพี้ยน
  • ถ้า query ว่างหรือเป็นช่องว่างล้วน จะคืนรายการเดิมทั้งหมด (ถือว่าไม่กรอง)
  • ใช้วิธี split query เป็นหลายคำ (terms[]) แล้วบังคับให้ทุกคำต้องแมตช์ใน text เดียวกัน
Flow 4

Pagination + Virtual Scroller + Chunk Array Paging

ตัวดักสำคัญ: ถ้า page เกินจำนวนหน้าจริง จะถูก reset เป็น 1 และทุกครั้งที่เปลี่ยนจำนวนรายการต่อหน้า ระบบจะบังคับกลับไปหน้าแรกเสมอ

  • itemsPerPage = "All" → แสดงทั้งหมดในหน้าเดียว แต่ส่งเข้า Virtual Scroller แบบแบ่งกลุ่ม 2 ตัวต่อแถว ผ่าน Utils.chunkArray(all, 2)

  • watcher ของ itemsPerPage รีเซ็ต page เป็น 1 เพื่อป้องกันกรณีที่ page เดิมเกินจำนวนหน้ารูปแบบใหม่
