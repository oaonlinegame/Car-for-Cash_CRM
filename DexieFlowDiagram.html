📘 คู่มือหลักการทำงาน: Lead Manager (Virtual Scroll Optimized)

นี่คือภาพรวมของสถาปัตยกรรมและการไหลของข้อมูล (Data Flow) ในระบบ Lead Manager ของคุณ ซึ่งถูกออกแบบมาโดยเน้นประสิทธิภาพสูงสุดสำหรับข้อมูลหลักหมื่นรายการ

---

🧠 หลักการทำงานและหน้าที่ของแต่ละโมดูล

ระบบถูกแบ่งเป็นชั้น (Layers) ชัดเจน เพื่อให้การจัดการข้อมูลและการแสดงผลเป็นอิสระต่อกัน:

ไฟล์/โมดูล หน้าที่หลัก (Responsibility) หัวใจของการทำงาน
dexie.js (AppDexie) Storage Layer (ฐานข้อมูล): จัดการการบันทึกและดึงข้อมูลถาวรทั้งหมดจาก IndexedDB ในเบราว์เซอร์ เป็นผู้ให้บริการฟังก์ชัน CRUD (Create, Read, Update, Delete) ให้ LeadApp
store.js (Store) Memory Layer (หน่วยความจำ UI): เป็นตัวกลางเก็บข้อมูลสำหรับ UI โดยใช้ shallowReactive + Object.freeze เก็บข้อมูลที่ Optimize แล้ว (Store.data.leadItems) เพื่อให้ UI (gui.js) ดึงไปใช้โดยตรง
lead.js (LeadApp) Business Logic: จัดการวงจรชีวิตของ Lead (เพิ่ม, ลบ, แก้ไข, โหลดทั้งหมด) สั่งการ: ดึงจาก AppDexie และส่งไปอัปเดตที่ Store
gui.js (AppGui) UI Logic: จัดการการค้นหา การแบ่งหน้า (Pagination) และ Virtual Scroll คำนวณ: ดึง Store.data.leadItems มาสร้าง Computed Properties เช่น pagedLeads
state.js (AppState) UI State: เก็บสถานะเปิด/ปิดเมนู, ค่าค้นหา, หน้าปัจจุบัน, ข้อมูลที่กรองแล้ว เป็นกล่องเก็บค่ากลางที่ทุกไฟล์อ่าน/เขียนได้
---

🔄 ลำดับเหตุการณ์ตั้งแต่เปิดเว็บ (Startup Flow)

นี่คือสิ่งที่เกิดขึ้นตั้งแต่ `index.html` เริ่มโหลดจนถึงการ์ด Lead ปรากฏบนหน้าจอ:

ภาพรวม Data Flow: IndexedDB ➡ (AppDexie.getAll) ➡ LeadApp.loadAll() ➡ Store.setItems() ➡ Store.data.leadItems ➡ (Computed Property ใน gui.js) ➡ AppState.pagedLeads ➡ UI (v-for / v-virtual-scroll)

ขั้นตอนที่ 1: เตรียมพร้อม (Setup)

ไฟล์ที่ทำงาน: index.html, dexie.js, store.js, state.js
  • ไฟล์พื้นฐานโหลด (Vue, Vuetify, Dexie).
  • dexie.js: สร้างฐานข้อมูล AppDexie และกำหนดตาราง leads ไว้รอรับคำสั่ง.
  • store.js: สร้าง Store ที่มี leadItems เป็น shallowReactive (พร้อมรับข้อมูลขนาดใหญ่).
  • state.js: สร้าง AppState เพื่อเก็บค่า UI ต่าง ๆ (หน้าปัจจุบัน, ค่าค้นหา).

ขั้นตอนที่ 2: เริ่มต้นแอปและการดึงข้อมูล (Bootstrap & Fetch)

ไฟล์ที่ทำงาน: app.js, lead.js, store.js
  • app.js: เริ่มต้นแอป Vue และรันฟังก์ชัน setup().
  • การเรียกหลัก: LeadApp.loadAll() ถูกเรียกใช้ทันที.
  • LeadApp.loadAll() สั่ง AppDexie.lead.getAll() เพื่อดึงข้อมูล Lead ทั้งหมดจาก IndexedDB.
  • LeadApp ส่งข้อมูลไปที่ Store.setItems('Lead', items).
  • Optimization: Store.setItems() สร้างรายการใหม่ที่ Object.freeze() ทุกรายการ แล้วกำหนดทับ Store.data.leadItems.

ขั้นตอนที่ 3: ประมวลผลและแสดงผล (Render)

ไฟล์ที่ทำงาน: gui.js, index.html (Template)
  • app.js เรียก AppGui.setupComputed().
  • gui.js สร้าง **Computed Properties** โดยดึงข้อมูลจาก Store.data.leadItems:
    • คำนวณ filteredLeads (รายการหลังค้นหา).
    • คำนวณ totalPages และ pagedLeads (รายการที่จะแสดง).
  • UI ใน index.html ใช้ v-for หรือ v-virtual-scroll วนลูปอยู่บน AppState.pagedLeads.
  • ผลลัพธ์: ข้อมูล Lead แสดงผลบนหน้าจออย่างรวดเร็วและลื่นไหล.
---

🚀 จุดเน้นประสิทธิภาพ (Optimization Keys)

ประสิทธิภาพที่เพิ่มขึ้นมานั้น มาจาก 2 เทคนิคหลักที่ทำงานร่วมกัน:

1. การจัดการหน่วยความจำที่รวดเร็ว (Store.js)

  • Vue.shallowReactive: บอก Vue ว่าให้เฝ้าดูแค่ตัวแปร leadItems ทั้งก้อนเท่านั้น (ห้ามเฝ้าดูการเปลี่ยนแปลงของ Object แต่ละตัวใน Array) ทำให้เมื่อมีข้อมูล 10,000 รายการ Vue ไม่ต้องสร้าง Watcher ถึง 10,000 ตัว
  • Object.freeze(): ข้อมูลแต่ละรายการที่ถูกส่งเข้า Store จะถูกแช่แข็ง (ทำให้เป็น Read-Only) เพื่อลดภาระการจัดเก็บและประมวลผลของ JavaScript Engine
  • Replace Reference: เมื่อมีการอัปเดต จะใช้วิธีเปลี่ยน Store.data.leadItems = newList แทนการใช้ push() หรือ splice() ซึ่งเป็นวิธีที่เร็วที่สุดสำหรับ shallowReactive

2. การจัดการ UI ที่ประหยัด (Virtual Scroll)

  • Virtual Scroll: เมื่อผู้ใช้เลือก 'All' UI จะไม่พยายามเรนเดอร์การ์ด Lead ทั้งหมด 10,000 ใบ แต่จะเรนเดอร์เพียงแค่ ~20-30 ใบ ที่มองเห็นอยู่บนหน้าจอเท่านั้น
  • ผลลัพธ์: ทำให้หน้าเว็บสามารถจัดการกับข้อมูลนับหมื่นรายการได้ โดยที่เบราว์เซอร์ยังคงลื่นไหลและใช้หน่วยความจำน้อยลงมาก

การแยกหน้าที่เหล่านี้ทำให้คุณสามารถแก้ไขโค้ดได้ง่ายขึ้น เช่น หากต้องการเปลี่ยนวิธีการค้นหา ก็ไปแก้แค่ utils.js โดยไม่กระทบต่อ store.js หรือ dexie.js ครับ
